# 회계관리 1급 · accounting-pass

회계관리 1급 개인용 기출 학습 사이트. 2023~2026년 30개 회차의 기출 2,400문항과 회차별 답안 MD를 연결했습니다. 2023·2024·2025년은 각 8회차, 2026년은 6회차입니다.

## 실행

Python 3와 Node 22 이상을 사용합니다. Supabase 클라이언트를 번들하므로 먼저 `npm ci`를 실행합니다.

```sh
npm ci
npm run build
python3 -m http.server 5173 --directory dist
```

브라우저에서 http://localhost:5173 을 엽니다. index.html을 파일로 직접 열면 문제 JSON을 불러오지 못할 수 있습니다.

## 구현된 기능

- 회차·과목·유형·검색·미학습 필터, 한 문제씩 풀이
- 제출 전 정답 숨김, 공식 확정답안 기준 즉시 채점 및 답안 출처
- 확신도, 오답·불확실·복습일 도래 문제 모아 풀기
- 확실하게 맞힌 횟수에 따라 1·3·7·14·30일 복습 간격, 오답·불확실은 1일
- 북마크, 메모 자동 저장, 유형 이름 수정
- 현재 문제 이어하기, JSON 기록 내보내기·가져오기
- 모바일 대응, 원문 표·보기 표시

## 자료 및 해설 상태

- sources/: 사용자가 공개를 승인한 기출문제 30개와 답안 30개, 총 MD 60개를 그대로 보존
- scripts/build.py: 문항 분리·답안 연결·자동 유형 분류·안전한 HTML 변환
- dist/questions.json: 2,400문항. 재무회계 1~40번, 세무회계 41~80번
- dist/import-report.json: 원문 누락 점검 결과
- 9월 47·50·55번에는 첨부 MD상 ④ 보기가 없습니다. 임의 복원하지 않고 기본 출제에서 제외했습니다. 2026년 학습 가능 문항은 477개입니다. 전체 연도에서 학습 가능한 문항은 2,393개입니다. 홈에서 누락 원문을 볼 수 있습니다.
- 유형은 규칙 기반 자동 분류 초안입니다. 확정된 전문가 분류가 아니며 문제 화면에서 수정할 수 있습니다.
- 공식 확정답안과 자체 작성한 문제 해설은 별도 표시합니다. 공식 해설은 제공된 자료에 없습니다. 2026년 480문항 각각의 정답 근거 또는 계산 과정을 content/explanations.json에 별도로 작성했습니다. 보기 누락 3문항은 원문 확인 필요 상태이며, 나머지 477문항은 제출 후 개별 해설을 표시합니다. AI API 호출이나 실시간 해설 생성 기능은 없습니다.
- 문제에 기재된 출제연도·세율·일반기업회계기준을 기준으로 학습합니다.
- 같은 문제의 반복 출제 탐지, 전체 과목 분류 검수, 실전 모의고사는 후속 개발 범위입니다. 로그인과 학습 기록의 기기간 동기화를 지원합니다.

## Netlify 무료 플랜 배포

Netlify는 무료 플랜을 제공하는 호스팅 서비스이며, 오픈소스 소프트웨어 자체는 아닙니다. 무료 제공량과 기능은 계정의 현재 요금제를 확인하세요.

### 방법 1: 바로 올리기

1. 저장소를 내려받고 `python3 scripts/build.py`를 실행합니다.
2. Netlify에서 수동 배포 기능을 선택합니다.
3. index.html이 바로 들어 있는 폴더(dist 내용)를 올립니다.

### 방법 2: GitHub 연결

1. Netlify에 로그인하고 GitHub에서 기존 프로젝트 가져오기를 선택합니다.
2. GitHub 접근 권한을 연결한 뒤 **MANI907/accounting-pass** 저장소를 선택합니다.
3. 배포 브랜치를 `main`으로 설정합니다.
4. 포함된 netlify.toml이 build command `npm run build`, publish directory `dist`를 지정합니다.
5. Python 3를 제공하는 빌드 환경에서 배포합니다. 문제 JSON은 빌드로 생성되므로 위 빌드 명령을 유지하세요. 수동 배포 시에는 로컬에서 먼저 빌드한 dist 폴더를 사용하세요.

**개인용과 비공개는 다릅니다.** 학습 UI는 로그인 후 사용할 수 있으며, 학습 기록과 메모는 계정별 행 단위 접근 제어로 보호합니다. 기출문제 정적 원본 자체는 공개 배포 자료입니다. 일반 정적 배포의 URL에 접근할 수 있는 사람은 문제 파일을 볼 수 있습니다. 비공개 GitHub 저장소만으로 배포 사이트가 비공개가 되지는 않습니다. 호스팅의 접근 제어 지원을 확인하거나, 혼자만 사용하려면 로컬에서 실행하세요. GitHub 공개 저장소에는 사용자 승인에 따라 앱 코드와 첨부 기출 MD 60개가 포함되어 있습니다. 공개 사이트는 https://accounting-pass-sjeon907.netlify.app 입니다. 현재 수동 배포이며 GitHub 수정이 자동 배포되지는 않습니다.

## 기록 저장

풀이 이력·복습 일정·북마크·문제별 풀이 노트·분류 수정·마지막 문제와 메모장을 로그인한 Supabase 계정에 보관합니다. 브라우저에는 계정별 캐시와 서버 전송 대기열을 두며, 연결 복구 시 동기화합니다. 로그인 전에는 학습 화면과 백업 관리 화면을 열 수 없습니다. 로그인 세션은 브라우저에 유지되며 명시적으로 로그아웃하면 로그인 화면으로 돌아옵니다.

기존 `hoedok-records-v1`·`hoedok-current`·`accounting-pass-memos-v1` 원본은 보존합니다. 처음 로그인한 뒤 상단 **이전 기록 가져오기**를 누르면 계정에 없는 기록과 메모를 추가합니다. 이미 계정에 있는 문제의 풀이·노트·북마크는 유지합니다. 백업 가져오기는 사용자가 선택한 동일 문항 기록을 덮어쓰며, 정답 여부는 현재 공식 답안과 다시 비교합니다.

## 문제 해설 관리

content/explanations.json의 문항 ID별 text에 개별 해설을 관리합니다. answer는 공식 확정답안과 일치해야 하며, sourceHash는 해당 문항 원문의 SHA-256입니다. 문제 원문 또는 정답이 바뀌면 빌드를 중단하여 기존 해설이 다른 문제에 잘못 연결되는 것을 방지합니다. 자체 작성한 학습용 해설이며 공식 해설이나 전문가 검수본은 아닙니다. 생성형 API 호출 없이 정적 파일로 제공됩니다.

## 시험 전 메모장

북마크 오른쪽 메모장 탭에서 제목·본문을 작성하고 자동 저장합니다. 제목·본문 검색, 수정, 삭제를 지원하며 최대 1,000개, 제목 120자, 본문 20,000자까지 저장합니다. 메모장은 로그인 후 본인 계정에 보관하며 다른 계정에 노출되지 않도록 RLS를 적용합니다. 새 백업(v2)에 문제 기록과 메모장이 함께 포함됩니다. 기존 백업(v1)은 현재 메모장을 건드리지 않으며, v2를 가져올 때 같은 ID의 메모는 수정시각이 더 최신인 내용을 유지합니다. 서버에 저장 완료된 메모는 다른 기기에서 같은 계정으로 불러올 수 있습니다. 서버에 아직 전송되지 않은 임시 내용은 브라우저 저장소 삭제 시 사라질 수 있습니다.

## 계정 메모 저장 연결

Supabase 무료 플랜의 `accounting-pass` 프로젝트(`qtztcbpjmymvolejmkqt`, 서울 리전)에 메모 테이블과 본인 계정 접근 정책을 생성했습니다. 공개 클라이언트 설정도 연결했습니다. 사용자가 Auth URL 설정을 저장했으며, 확인 링크의 사이트 복귀 주소를 검증했습니다.

- `database/cloud-memos.sql`: 본인 계정만 SELECT/INSERT/UPDATE할 수 있는 RLS, 버전 조건부 수정, 삭제 동기화용 tombstone. 브라우저에서 `service_role` 키를 사용하지 않습니다.
- `dist/cloud-config.json`: Supabase 프로젝트 URL과 **publishable key**만 설정합니다. 두 값은 공개 클라이언트 설정이며 비밀키를 넣으면 안 됩니다. 비어 있거나 연결에 실패하면 로그인 화면에 연결 상태를 표시하고 학습 화면은 열지 않습니다.
- `src/cloud-client.mjs`, `scripts/build-web.mjs`: 고정 버전 Supabase SDK를 로컬 번들합니다. `npm ci && npm run build`로 배포 파일을 생성합니다.
- 프로젝트의 Auth URL Configuration(https://supabase.com/dashboard/project/qtztcbpjmymvolejmkqt/auth/url-configuration)에서 Site URL을 `https://accounting-pass-sjeon907.netlify.app`으로 설정하고 Redirect URLs에 `https://accounting-pass-sjeon907.netlify.app/`을 허용해야 가입 확인·비밀번호 재설정 링크가 이 사이트로 돌아옵니다. 이메일/비밀번호 가입과 이메일 확인을 사용합니다. Supabase 기본 메일 발송은 조직 구성원 주소로 제한될 수 있어 타인 가입을 확대할 때 별도 SMTP 설정이 필요합니다.
- 메모장 → 로그인/가입 → **계정으로 복사**로 브라우저 메모를 가져옵니다. 원본 브라우저 메모는 유지하며 같은 원본은 중복 복사하지 않습니다. 다른 기기는 같은 이메일로 로그인합니다.
- 서버 응답을 확인한 뒤에만 `계정에 저장됨`을 표시합니다. 네트워크 오류 시 계정별 캐시에 대기 중 편집을 보관하고 재연결·창 활성화·30초 주기로 재시도합니다. 서버 저장 완료 전 브라우저 데이터를 지우면 대기 내용은 사라질 수 있습니다.
- 동시에 수정하면 서버의 최신 내용을 유지하면서 로컬 편집을 `(기기 사본)`으로 추가합니다. 오래된 기기의 삭제가 최신 수정본을 지우지 않도록 합니다. 로그아웃한 계정의 캐시는 다른 계정에 표시하거나 전송하지 않습니다.
- 백업 v2는 현재 열려 있는 메모장의 내용을 포함합니다. 계정에 로그인한 상태에서 백업을 가져오면 해당 계정의 저장 대기열에 추가합니다. 풀이 기록·북마크·문제별 풀이 노트도 같은 계정에 저장합니다.
- 현재 29개 단위 테스트와 DOM 회귀 검증을 통과했습니다. 원격 DB에서 본인 메모 작성·조회·수정, 타 계정 읽기·쓰기 차단, 비로그인 차단, 수정 버전 충돌 및 삭제 동기화를 검증했고 테스트 데이터는 트랜잭션 롤백으로 제거했습니다. 공개 REST API도 비로그인 접근을 401로 거절합니다. 데이터 접근 정책 관련 보안 지적은 없습니다. Auth 검사에는 [유출 비밀번호 검사 미사용](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) 안내가 남아 있으며, 해당 기능은 Pro 이상 요금제에서 지원합니다. 무료 플랜을 유지합니다. 실제 이메일 수신과 비밀번호 재설정의 전체 왕복은 사용자 계정으로 수행해야 합니다.

- `dist/memo-account.mjs`의 기존 인증을 사이트 전체에서 공유합니다. 유효한 로그인 세션은 복원하고, 로그아웃·세션 종료 시 학습 UI·기록·열린 백업 창을 비웁니다.
- `database/cloud-study.sql`은 `study_events` 테이블과 본인 계정만 SELECT/INSERT할 수 있는 RLS를 정의합니다. 브라우저에 UPDATE/DELETE 권한을 주지 않습니다. 기존 `study_memos` 데이터와 계정은 유지합니다.
- `dist/study-sync.mjs`는 풀이·북마크·노트·유형·마지막 문제 변경을 고유 ID의 이벤트로 저장합니다. 재전송은 같은 ID로 중복 제거하며, 여러 기기에서 푼 이력을 합쳐 풀이 횟수와 복습 일정을 재계산합니다. 별개 필드의 변경은 서로 덮어쓰지 않습니다. 같은 노트·유형을 여러 기기에서 수정하면 변경 시각 순으로 최종 값을 표시하며 이전 이벤트도 서버에 남습니다.
- 브라우저 캐시와 대기열은 계정 ID로 분리합니다. 네트워크 오류 시 임시 보관 후 자동 재시도하고 상단에 상태를 표시합니다. 저장 응답이 유실된 작업의 ID를 이후 입력에 재사용하지 않아 후속 편집 내용이 사라지지 않도록 합니다.
- 원격 DB에서 본인 데이터 추가·조회, 중복 재전송, 타 계정 읽기·쓰기 차단, 비로그인 차단과 불변 이벤트 권한을 트랜잭션 안에서 검증했습니다. 모든 테스트 데이터는 롤백했으며 사용자 메모는 변경하지 않았습니다.

## 교재 목차 기반 유형별 학습

유형별 학습은 사용자가 제공한 교재 목차를 기준으로 재무회계 4편·18단원, 세무회계 6편·14단원을 표시합니다. 현금흐름표와 원천징수는 하위 장이 없는 단일 단원입니다. 연도와 과목을 선택하고 장별 문제 풀기·복습을 시작할 수 있습니다. 진행률은 최근 풀이가 정답이면서 확신도가 ‘확실해요’인 문항 수를 전체 문항 수로 나눈 값입니다. 빈 단원도 목차에 남으며 학습 버튼은 비활성화됩니다.

- `scripts/curriculum.py`: 목차 정의와 출제 내용을 우선하는 분류 규칙. 문제당 대표 단원 하나를 지정합니다.
- `content/chapter-overrides.json`: 규칙으로 명확히 구분하기 어려운 문항의 개별 분류. 추가·수정 후 다시 빌드합니다.
- `dist/curriculum.json`: 빌드 시 생성하는 목차 메타데이터.
- `dist/curriculum.mjs`: 개인 분류를 반영하는 단원 조회와 학습 현황 집계.
- `tests/curriculum.test.mjs`: 목차 누락·중복 및 과목 혼합 방지, 경계 문항, 기존 백업 호환성, 확신도 집계 검증.

분류는 교재의 세부 본문까지 대조한 전문가 확정본이 아닌 규칙 기반 초안입니다. 단기매매증권은 당좌자산, 매도가능·만기보유·지분법과 유가증권 일반은 투자자산으로 분류합니다. 선급비용·미수수익은 당좌자산, 선수수익은 유동부채, 사채는 비유동부채, 이연법인세는 재무회계 재무상태표의 이연법인세 장에 배치합니다. 과세거래에는 공급시기를, 법인세 계산 단원에는 세무조정·소득처분을 포함합니다. 원천징수와 세금계산서는 별도 편입니다. 복합 문항은 대표 단원만 지정하여 중복 집계를 피합니다.

기존 문항 ID·원문·선택지·공식 답안·해설·기존 세부 유형을 유지하고 `chapterId`, `partName`, `chapterName`, `classificationStatus`만 추가합니다. 과거 개인 유형 이름은 문제 화면에 표시하며 자동 변경하지 않습니다. 사용자가 단원을 직접 수정하면 기존 동기화 `topic` 필드에 `curriculum:단원ID`를 저장하므로 서버 스키마와 백업 버전을 변경할 필요가 없습니다. 같은 과목의 유효한 단원만 개인 분류로 사용합니다. 학습 기록과 원격 계정 데이터에 대한 일괄 마이그레이션은 수행하지 않습니다.
